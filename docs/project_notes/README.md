# Progress note: build and reproduce

`jinchen_progress.tex` is an English REVTeX note, with a compact title and no
abstract or separate title page. Its figures are vector PDF files in `figs/`.
The scientific text describes the algorithms independently of source filenames.
The note omits the pipeline diagram and the numerical-validation section;
their underlying measurements and figure files remain in the result archive.
The concise revision keeps four sections, three distribution/scale figures,
and the two-flow training and validation loss figure,
the frozen downsampling coefficients and compact held-out result tables.
The loss figure has one panel per flow, showing the total mean-plus-width
distribution objective. Likelihood and paired-link warm-up losses are omitted;
Flow 2's final calibration is a separate segment because its weighting and
warm start differ from Adam training.
The upsampling distribution figure separates Flow 1 against the smoothed
fine references from the final two-flow output against original fine references.
The Flow-1 loop panels use marked broken axes to show their large separation;
both visible windows have the same horizontal scale.
Detailed fit records, calibration offsets and intermediate comparisons
remain in `results/` rather than the main text.

Run from the repository root to rebuild figures using the archived measurements:

```bash
.venv/bin/python docs/project_notes/make_figures.py
.venv/bin/python docs/project_notes/update_results.py
cd docs/project_notes
tectonic --keep-logs jinchen_progress.tex
```

works. Figures are embedded in the exported PDF. The TeX source uses relative

The earlier evaluations remain archived. The current note shows the completed

The compact `results/` archive contains reference potential and autocorrelation

Defaults use seed 1234, 12 training configurations, eight validation configurations, all 60
test configurations, 8/2 flow sweeps and 4/20/3/20 Adam epochs. Each six-offset
calibration has a 30-objective-evaluation budget. Finite-difference Jacobian
passes require additional forward measurements. CUDA and existing NERSC
ensembles are required; no heatbath ensemble is regenerated by these commands.
Training a fresh run computes its frozen-smear cache if necessary.

The recorded experiment resumed after three likelihood epochs to enable an
analytic CUDA frame solver with a CPU near-collision fallback, then resumed
at the completed Flow-1 boundary to enable paired-transport validation
selection. Its exact invocations, discarded partial work and execution
history are preserved in the result archive. Optimizer states were restarted
at those boundaries, so uninterrupted training is a reproduction of the
method and settings rather than a promise of identical weights.

A subsequent interruption during paired epoch 2 was recovered from the saved
paired epoch-1 checkpoint, with two paired epochs remaining and Adam state

completed the 4/20/3/20 training phases, both calibrations and all 60 test

The failure is archived in `results/L12_to_L24_2flow_equivariant_v2/validation.log`.

mean shifts are approximately 1.068, 0.513, 0.425 and -0.130 target widths;
